# セットアップ手順(詳細)

[README](../README.md) の「セットアップ」を、画面の操作つきで説明します。所要時間は 10〜15 分です。

登場するアカウントは 2 つです。

- **仕事アカウント**: 会社の Google Workspace アカウント。手順 1 だけで使います
- **個人アカウント**: 個人の Gmail。スクリプトはこちらで動かします

## 1. 仕事カレンダーを個人アカウントに共有する

**仕事アカウント**で Google カレンダーを開きます。

1. 左の「マイカレンダー」で自分のカレンダーにカーソルを合わせ、「︙」→「設定と共有」を開く
2. 「共有する相手」の「ユーザーやグループを追加」をクリック
3. 個人の Gmail アドレスを入力し、権限を **「予定の変更」** にして送信

<!-- スクショ: 共有する相手の追加ダイアログ(権限「予定の変更」を選択した状態) -->

「予定の変更」が必要な理由は 2 つあります。仕事の予定のタイトルと場所を読むためと、仕事カレンダーに「予定あり」ブロックを書き込むためです。

> 権限の選択肢に「予定の変更」が出てこない、または選ぶとエラーになる場合は、会社が外部アカウントへの共有を制限しています。その環境では本ツールは使えません。

## 2. 個人アカウント側でカレンダーを追加する

**個人アカウント**の Gmail に「カレンダーを共有しました」というメールが届きます。メール内の「このカレンダーを追加」をクリックしてください。

個人アカウントの Google カレンダーで、左の「他のカレンダー」に仕事カレンダーが表示されれば成功です。

<!-- スクショ: 他のカレンダーに仕事カレンダーが追加された状態 -->

> この追加を忘れると、後の手順で「仕事カレンダーが見つかりません」というエラーになります。

## 3. GAS プロジェクトを作る

**個人アカウント**で [script.google.com](https://script.google.com) を開きます(右上のアイコンで、個人アカウントになっていることを確認してください)。

1. 「新しいプロジェクト」をクリック
2. 左上の「無題のプロジェクト」をクリックして、名前を「いえとしごと」などに変える

## 4. コードを貼り付ける

エディタ左の「ファイル」の「+」→「スクリプト」で、次の 4 つのファイルを作ります。ファイル名に `.gs` は付けなくて構いません(自動で付きます)。

| 作るファイル名 | 貼り付ける内容 |
|---|---|
| `main` | [src/main.gs](../src/main.gs) |
| `workToPersonal` | [src/workToPersonal.gs](../src/workToPersonal.gs) |
| `debug` | [src/debug.gs](../src/debug.gs) |
| `config` | [src/config.example.gs](../src/config.example.gs) |

最初からある `コード.gs` は、削除するか、中身を空にして `main` として使ってください。

<!-- スクショ: 4つのファイルが並んだエディタ -->

> `config.example` という名前のファイルは作らないでください。`config` と両方あると、`CONFIG` が二重定義になって動きません。

## 5. config を書き換える

`config` ファイルの `WORK_EMAIL` を、自分の仕事用メールアドレスに書き換えます。必須の設定はこれだけです。

```js
WORK_EMAIL: 'taro.yamada@example.co.jp',
```

そのほかの項目(同期する日数、ブロックのタイトル、実行間隔など)は、既定値のままで動きます。変えたい場合だけ、該当する行の先頭の `//` を外して値を書き換えてください。

書き換えたら、Ctrl+S(Mac は ⌘+S)で保存します。

## 6. Calendar API を追加する

1. エディタ左の「サービス」の「+」をクリック
2. 一覧から **Google Calendar API** を選ぶ
3. 識別子が **`Calendar`** になっていることを確認して「追加」

<!-- スクショ: サービス追加ダイアログ(Google Calendar API、識別子 Calendar) -->

> 識別子を変えると動きません。`Calendar` のままにしてください。

## 7. タイムゾーンを確認する

1. 左の歯車アイコン「プロジェクトの設定」を開く
2. タイムゾーンを **「(GMT+09:00) 日本標準時 - 東京」** にする

終日予定のブロックを正しい日付で作るために必要です。東京以外になっていると、同期はエラーで止まります。

## 8. 同期される内容を確認する(何も変更しません)

いきなり同期する前に、何が同期されるかを確認します。

1. エディタ上部の関数の選択で `debugInspectEvents` を選び、「実行」をクリック
2. 初回は承認を求められます。「権限を確認」→ 個人アカウントを選択 →「このアプリは Google で確認されていません」と出たら「詳細」→「(プロジェクト名)(安全ではないページ)に移動」→「許可」
   - 自分で貼り付けたコードを自分のアカウントで動かすための承認です
3. 下部の「実行ログ」に、個人カレンダーと仕事カレンダーの予定が「対象」「対象外: 理由」つきで表示されます

<!-- スクショ: debugInspectEvents の実行ログ -->

個人の予定のうち同僚に時間を伝えたくないものが「対象」になっていたら、その予定を Google カレンダー上で「予定なし」に変えてください。

## 9. 手動で 1 回同期する

関数の選択で `syncBusyBlocksSafe` を選び、「実行」をクリックします。

- 仕事カレンダーに「予定あり」ブロックが、個人カレンダーに仕事の予定のコピーができていれば成功です
- **初回はレート制限のエラーで途中終了することがあります。これは正常です。** 60 日分を一度に作るためで、作れた分は残ります。数分おいてもう一度実行するか、そのまま次の手順に進んでください(自動実行が続きを作ります)

## 10. 自動実行を設定する

関数の選択で `setupTrigger` を選び、「実行」をクリックします。

左の時計アイコン「トリガー」を開き、`syncBusyBlocksSafe` の時間主導型トリガー(15 分おき)ができていれば完了です。

<!-- スクショ: トリガー一覧 -->

> `setupTrigger` は、このプロジェクトの既存トリガーをすべて削除してから作り直します。「いえとしごと」専用のプロジェクトで実行してください。

## 承認画面で「This app is blocked(このアプリはブロックされます)」と出たとき

個人の Gmail アカウントでは、自作のスクリプトの承認が Google にブロックされることがあります。その場合は、GAS プロジェクトを自分の Google Cloud プロジェクトに紐づけると承認できるようになります(無料です)。

1. 個人アカウントで [Google Cloud コンソール](https://console.cloud.google.com/) を開き、新しいプロジェクトを作る。ダッシュボードに表示される **プロジェクト番号**(数字)を控える
2. 「API とサービス」→「ライブラリ」で **Google Calendar API** を有効にする
3. 「API とサービス」→「OAuth 同意画面」を設定する。対象は **外部**、アプリ名と連絡先は自分のもの。作成後、「対象」の **テストユーザー** に自分の Gmail アドレスを追加する
4. GAS エディタの「プロジェクトの設定」→「Google Cloud Platform(GCP)プロジェクト」→「プロジェクトを変更」で、控えたプロジェクト番号を設定する
5. もう一度関数を実行し、承認画面で「続行」→「許可」

> 「テスト中」のままだと承認が 7 日で切れることがあります。切れると同期がエラーで止まり、通知メールが届くので、その場合は関数をもう一度実行して承認し直してください。
> 恒久的に使うなら、「対象(Audience)」で「本番環境に公開(Publish app)」に切り替えます。事前に「ブランディング」でホームページ URL とプライバシーポリシー URL(例: このリポジトリの URL と PRIVACY.md の URL)の入力と、承認済みドメインへの `github.com` の追加が必要です。

<!-- スクショ: GAS のプロジェクト設定で GCP プロジェクト番号を入力する画面 -->

> Google の「高度な保護機能プログラム」に加入しているアカウントでは、「Access blocked … Advanced Protection」と表示されて承認できません。

## うまくいかないとき

| 症状 | 確認すること |
|---|---|
| 承認画面で「This app is blocked」 | 上の「承認画面で『This app is blocked』と出たとき」の手順 |
| 承認画面で「Access blocked … Advanced Protection」(policy_enforced) | 個人アカウントが「高度な保護機能プログラム」に加入しています |
| 「config.gs の WORK_EMAIL が未設定です」 | 手順 5。サンプルのアドレスのままになっていないか |
| 「仕事カレンダーが見つかりません」 | 手順 1 の権限と、手順 2 の「このカレンダーを追加」 |
| 「Calendar is not defined」 | 手順 6。識別子が `Calendar` になっているか |
| 「Identifier 'CONFIG' has already been declared」 | `config` と `config.example` の両方を作っていないか |
| 「プロジェクトのタイムゾーンが東京ではありません」 | 手順 7 のタイムゾーン |
| 特定の予定が同期されない | `debugInspectEvents` を実行して、対象外の理由を確認 |
| 同期の管理から漏れた「予定あり」が残っている | `debugInspectBlocks` を実行し、「★孤児候補」を手動で削除 |
| エラー通知メール(件名「[いえとしごと] 同期エラー」)が届いた | 本文の「確認してほしいこと」に従う。心当たりがなければ、エラー内容をこの表と照らす。同じエラーの通知は 6 時間に 1 回です |
| 「Action not allowed」または「Forbidden」 | 手順 1。共有の権限が「予定の変更」になっているか |
| 「Not Found」 | 手順 2 の「このカレンダーを追加」と、手順 5 の仕事用アドレス |
